# P1 migration note

Revision `0001_p1_schema` creates the initial PostgreSQL/PostGIS control and
telemetry tables:

- organizations, vehicles, devices, and historical device assignments;
- raw JT/T 808 messages with a 30-day retention index;
- GPS positions partitioned by UTC GPS month;
- one unique `(device_id, gps_timestamp)` index per position partition; and
- the durable telemetry outbox.

The migration prepares twelve months of historical partitions plus future
partitions. The maintenance worker owns raw-frame deletion. Position retention
and downsampling policies will be expanded in P5 without changing the logical
deduplication key.

Run forward migrations with `alembic upgrade head` through the Compose
`migrate` service using Neon’s direct, unpooled connection URL. Runtime
services use the pooled URL. Do not run `alembic downgrade` against production:
dropping the P1 tables is destructive. Restore a database backup into a
disposable PostgreSQL instance if a rollback rehearsal is needed.
